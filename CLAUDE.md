# MHW Equipment Builder

A fan-made build simulator for **Monster Hunter: World** (base game + Iceborne). It recreates the in-game **Equipment change menu** as closely as possible so builds can be tested quickly, with live skill totals, weapon stats and EFR/EFE.

Fan-made, non-commercial, not affiliated with Capcom.

## Goal

Pick a weapon, armor, charm and decorations and immediately see:

- total skills (levels, max levels, set bonuses, secret-skill cap raises)
- weapon stats (attack, affinity, element/status, sharpness, slots, elderseal)
- defense and elemental resistances
- **EFR** (effective raw) and **EFE** (effective element)
- a stat diff preview (up/down) when hovering a candidate item, like in the game

Everything is unlocked: every weapon and armor piece is available, and armor is always fully upgraded. There is no inventory, crafting cost or material tracking.

## Scope

### v1
- Equipment screen replicating the in-game layout and behavior: slot list (Weapon, Head, Chest, Arms, Waist, Legs, Charm), tabbed right sidebar (Overall Stats / Overall Skills / Selected Equipment), hover-to-compare, info-rich center panel.
- **Weapon selection via crafting tree** (smithy-style), not a flat list.
- Armor selection (all ranks: Low, High, Master), always at max defense.
- Charms (max level).
- Decorations in slots (sizes 1 to 4, including Iceborne size-4 jewels with two skills).
- Skill totals with caps, set bonuses and secret skills.
- EFR/EFE calculator.
- Keyboard and gamepad navigation (Gamepad API) alongside mouse.
- Saved builds (localStorage) and shareable builds (build encoded in the URL).

### Later milestones
- Situational toggles (Agitator active, Weakness Exploit on weakspot, Peak Performance at full HP, etc.).
- monster hitzones
- crafting cost for armor and weapons

### Non-goals
- No backend, accounts or server-side storage.

## Tech stack

- **Vue 3** (Composition API, `<script setup>`), **Vite**, **TypeScript** in strict mode
- **Pinia** for state (current build, saved builds, UI focus)
- **Vitest** for unit tests
- **Playwright** for end-to-end tests
- Static site only: deployable to any static host (own VPS or GitHub Pages)

## Architecture

```
public/
  icons/          placeholder icons (see "Icons" below)
scripts/
  import/         converts the raw data source into normalized JSON
src/
  data/           generated, committed JSON (weapons, armor, charms, decorations, skills, set bonuses)
  engine/         pure TypeScript, no Vue imports
    skills.ts         skill totals, caps, set bonuses, secret skills
    skill-effects.ts  hand-written table: skill + level -> numeric modifiers
    weapon-stats.ts   true raw, element, sharpness, affinity
    efr.ts            EFR / EFE
    tree-layout.ts    weapon tree -> node grid positions + edges
    build-codec.ts    build <-> URL string
  stores/         Pinia stores
  components/     slot list, right sidebar (tabs + compare window), center panel, item pickers, weapon tree, decoration screen
  input/          focus grid + keyboard/gamepad navigation
  icons.ts        icon registry: icon ID -> file path
tests/
  e2e/            Playwright specs
```

Rules:
- **`engine/` must stay framework-free.** All math and layout logic lives there and is unit tested. Components only display results.
- **The app never calls an external API at runtime.** All data is generated by `scripts/import` and committed to `src/data/`.
- Every selectable UI element registers a position in the focus grid so keyboard and gamepad navigation work everywhere, not just mouse hover.

## Data

Candidate sources (to be decided after checking completeness, especially Iceborne/Master Rank):
- Gathering Hall Studios' open-source MHWorld data (MIT, CSV source files, includes Iceborne)
- mhw-db.com

The import script normalizes the chosen source into our own types (`Weapon`, `Armor`, `Charm`, `Decoration`, `Skill`, `SetBonus`), so the app never depends on the source format.

Requirements for the generated data:
- Weapons keep a reference to their **previous weapon** in the upgrade path so trees can be built.
- Armor stores only the **max** defense (augmented max for Master Rank armor).
- Charms are stored at their highest level only.
- Skill data includes max level and which set bonus / secret skill can raise it.

Data validation tests: every weapon's parent exists, no cycles in trees, every skill referenced by armor/decorations/charms exists, slot sizes are 1 to 4.

### Skill effects table

Data sources only describe skill effects in text. `engine/skill-effects.ts` is a hand-written table mapping each relevant skill level to numeric modifiers (flat raw, % raw, affinity, crit multiplier, flat element, % element, element crit, etc.) plus whether the effect is conditional. This table is the most likely source of bugs; every entry needs a test.

## Calculation rules

All constants below must be verified against a trusted reference and covered by tests with known in-game values before being treated as final. Keep them in one constants file.

- **True raw** = displayed attack / weapon-class bloat value.
  Bloat values: Great Sword 4.8, Long Sword 3.3, Sword & Shield 1.4, Dual Blades 1.4, Hammer 5.2, Hunting Horn 4.2, Lance 2.3, Gunlance 2.3, Switch Axe 3.5, Charge Blade 3.6, Insect Glaive 3.1, Light Bowgun 1.3, Heavy Bowgun 1.5, Bow 1.2.
- **Displayed element** = true element x 10.
- **Raw sharpness multipliers**: red 0.50, orange 0.75, yellow 1.00, green 1.05, blue 1.20, white 1.32, purple 1.39.
- **Element sharpness multipliers**: red 0.25, orange 0.50, yellow 0.75, green 1.00, blue 1.0625, white 1.15, purple 1.27.
- **Crit multiplier (raw)**: 1.25 base; Critical Boost raises it (1.30 / 1.35 / 1.40). Negative affinity uses 0.75.
- **EFR** = true raw x raw sharpness multiplier x (1 + affinity x (crit multiplier - 1)), using the negative-affinity multiplier when affinity < 0. Affinity is capped at 100%.
- **EFE** = true element x element sharpness multiplier x (1 + affinity x (element crit multiplier - 1)), where the element crit multiplier only applies with Critical Element (or Safi/Kjárr equivalents) and depends on weapon class. Look up the per-class values; do not guess them.
- Element boosts are limited by the **element cap**. Implement the cap rule from a reference, with tests.
- Percentage raw bonuses and flat raw bonuses must be applied in the correct order; confirm the order from a reference and test it.
- Gunner weapons (bowguns, bow) have no sharpness; EFR uses multiplier 1.0 for that term.

## UI

Goal: replicate the in-game Equipment change menu's **layout and behavior** as closely as possible.

### Layout

Three columns, like MH World:

| Left | Center | Right sidebar |
|------|--------|---------------|
| Slot list (Weapon, Head, Chest, Arms, Waist, Legs, Charm). Selecting a slot opens the item picker. | No player model, so this space shows extra info (see below). | Main information panel, always visible, tabbed. |

### Right sidebar (most important component)

The sidebar holds about 90% of the information. It works like the in-game one: switch tabs with the mouse, keyboard or gamepad shoulder buttons. The tabs are part of the focus grid.

Tabs:
1. **Overall Stats**: totals for the whole build: attack, affinity, element/status, sharpness, elderseal, defense, elemental resistances, EFR/EFE.
2. **Overall Skills**: every active skill with current level / max level pips, set bonuses (pieces equipped / required) and secret-skill cap raises.
3. **Selected Equipment**: stats, slots, decorations and skills of the equipment in the currently selected slot.

Hover / focus compare:
- Hovering or focusing a candidate item (in a picker or the weapon tree) opens a **second window** in the **Selected Equipment** tab. It sits next to the first one: currently equipped item vs. hovered item. Values that differ are colored and get up/down indicators.
- While the hover lasts, the **Overall Stats** and **Overall Skills** tabs show the build totals the change would produce as a diff (up/down, skills gained/lost).
- When the hover ends, the second window closes and every tab goes back to the equipped values.

### Center panel (improvement over the game)

The game shows the hunter model here. We use the space for information the game hides or spreads across several menus:
- The item picker, weapon tree and decoration screen open here when a slot is selected.
- With no picker open, show a build overview: the full equipment list with slots and decorations, an EFR/EFE breakdown (true raw, sharpness multiplier, affinity, crit multiplier) and full descriptions of the active skills.
- This content can grow over time, but it should not repeat what the sidebar already shows as its main content.

### Other screens and behavior

- Decoration screen: pick a slot, filter decorations by slot size.
- Weapon tree screen:
  - Row of the 14 weapon type icons at the top.
  - Each tree (Ore, Bone, monster trees, ...) is a horizontal band. Column = depth in the upgrade path; rows = depth-first order so siblings stack.
  - Connector lines in one SVG layer behind the nodes, drawn from positions computed by `engine/tree-layout.ts`.
  - Hover/focus shows the stat diff; select equips.
  - Search box that jumps to and highlights a weapon.
  - "Special" tab for Kulve Taroth and Safi'jiiva weapons (later milestone).
- Controls: keyboard (arrows, Enter, Escape, tab switching)
- Sharpness bars are drawn with CSS, not images.

## Testing

- **Vitest** (`engine/` and stores): skill totals and caps, set bonuses, secret skills, EFR/EFE against known values, tree layout, build URL encode/decode round trip, data validation.
- **Playwright** (`tests/e2e/`): main user flows:
  - equip a weapon from the tree and see the stats update
  - equip armor and see skill totals update
  - slot a decoration (size rules enforced)
  - hover diff preview opens the comparison window in the Selected Equipment tab with correct up/down values
  - save a build, reload, load it again
  - open a shared build URL and get the same build
  - complete a full build using keyboard only

Engine changes require unit tests. UI flow changes require updating the Playwright specs.
