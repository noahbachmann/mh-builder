# src/engine — pure TS damage/skill model

No Vue imports. Everything takes a `DataIndex` (`src/data/index.ts`) so tests can pass fixtures.

- `build.ts`: `Build` = ids only (weapon, 5 armor, charm, decos per slot). Immutable helpers `equip` (clears that slot's decos, like in-game) and `setDecoration` (enforces deco size <= slot size).
- `skills.ts`: `computeSkills` sums weapon/armor/charm/deco skills + active set-bonus skills (each grants level 1). "X Secret" skills (`Skill.unlocks`) raise X's cap to `unlockedMaxLevel`. `points` = raw sum, `level` = capped. `skillUnlockers` lists the secrets (and the set bonuses granting them) that raise a skill's cap, for the infobox.
- `skill-effects.ts`: hand table skill+level -> modifiers. Raw = TRUE raw, element/status = DISPLAYED. `conditional` effects are skipped unless `includeConditional` (all) or their skill id is in `conditions`; `CONDITIONAL_SKILLS` lists skill id + condition label for toggles. `skill-effects.test.ts` cross-checks every number against the in-game text in `skills.json`; add to `IGNORED` only for text parts we don't model.
- `constants.ts`: every constant with its source. `elementCap()` is UNVERIFIED and returns null (uncapped).
- `weapon-stats.ts`: true raw = base x multipliers + flat; element = base x % + flat. Hidden element needs Free Element. NEB only without active element (bowguns: no elemental ammo). Sharpness stored at Handicraft 5, trimmed from the top.
- `efr.ts`: EFR/EFE with breakdowns. Gunners sharpness 1.0. Element crit only on positive affinity. `rawAffinityFactor` / `elementAffinityFactor` hold the crit rule for everyone.
- `evaluate.ts`: one call -> `BuildStats` (skills, weapon, efr, efe, defense). `build-diff.ts` diffs two `BuildStats` for hover compare.
- `build-compare.ts`: `compareBuilds(entries)` -> metric rows (values, `best` indices, deltas vs first build; higher is always better; no `best` on full ties), skill + set bonus matrix. `evaluateForCompare` adds a `potential` evaluation with `includeConditional` (EFR with every situational skill active).
- `tree-layout.ts`: band per root, DFS rows. Columns grouped by rarity (`rarityCols`): col = rarity group start + index among consecutive same-rarity ancestors. `edgePath` makes elbow SVG paths with the vertical right before the child (edges can skip columns).
- `build-codec.ts`: `1.` + 7 `_`-joined items, base36 ids, `-` decos, `x` empty. Decoder drops invalid parts.
- `hitzone-damage.ts`: damage per hit vs a `Monster` (data in `src/data/monsters.ts`, lazy). `monsterParts(m, mode, broken)` picks per part the most specific hitzone row (mode variant > base, `Broken` per part); parts only in other modes are dropped. `hitDamage` = raw (x MV, x raw HZV of the weapon's `damageType`) + element (averaged over two elements). Weakness Exploit is per row (HZV >= 45 after `tenderize`, + `woundAffinity` when wounded), so builds must be evaluated with `evaluateForMonster` (drops WEX from `conditions`); `DamageSettings.weaknessExploit: false` switches it off. `damageTable` / `weightedAverage` feed the Damage Output tab. Raw/element kept apart for a later DPS mode.
